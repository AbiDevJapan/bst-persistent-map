# Step 9.0.1 — Revised conventional localization with point-to-plane ICP

Step 9.0.1 revises only the **matcher** after the real Step 9.0 NCLT run showed that dense nearest-voxel point-to-point ICP could terminate with a tiny update while remaining almost exactly at the injected pose perturbation.

The data, map representation, cross-session protocol, perturbation levels, success thresholds, and 3-DOF state are kept fixed so that Step 9.0.1 is a controlled matcher-only experiment.

## What changes from Step 9.0

Step 9.0 used:

- 3-D nearest voxel-center correspondence;
- trimmed point-to-point residual;
- absolute planar SE(2) least-squares update.

Step 9.0.1 uses:

- the same 3-D nearest voxel-center correspondence search;
- lazily estimated PCA normals on the conventional voxel map;
- rejection of ground-like normals that weakly constrain x/y/yaw;
- trimmed point-to-plane residuals;
- damped Gauss-Newton updates over x/y/yaw.

Map normals are **not precomputed for the entire 5M+ voxel map**. They are estimated only for target voxel centers needed by the current trial and cached for that trial.

## Frozen benchmark protocol

Defaults remain:

- map session: `2012-01-15`;
- query session: `2012-02-02`;
- map voxel size: 0.5 m;
- 20 query scans;
- perturbations: `0.5:1,1:3,2:5,5:10`;
- local map radius: 40 m;
- optimized state: x, y, yaw;
- z, roll, pitch fixed from NCLT reference pose;
- success: <= 0.5 m translation and <= 1 degree yaw.

The local map is still retrieved around the **perturbed initial pose**, never around ground truth.

## Exact replay of Step 9.0 scans

For the cleanest comparison, pass the `query_scans.csv` generated by your Step 9.0 run:

```bash
python3 run_step9_0_1.py \
  --data-root data \
  --map-session 2012-01-15 \
  --query-session 2012-02-02 \
  --query-scans-csv results/step9_0_localization/query_scans.csv \
  --voxel-size 0.5 \
  --scan-stride 10 \
  --query-count 20 \
  --perturbations 0.5:1,1:3,2:5,5:10 \
  --localization-max-range 30 \
  --scan-downsample 0.75 \
  --max-scan-points 8000 \
  --local-map-radius 40 \
  --icp-max-correspondence 2.0 \
  --output results/step9_0_1_point_to_plane
```

If `--query-scans-csv` is omitted, the deterministic Step 9.0 selection procedure is used.

The perturbation seed remains `42090`, so when scan order and perturbation list are unchanged the same perturbation direction/yaw sign sequence is reproduced.

## Point-to-plane defaults

- normal neighbors: 16;
- normal neighborhood maximum radius: 1.5 m;
- minimum normal neighbors: 6;
- maximum PCA curvature: 0.20;
- minimum horizontal normal component: 0.20;
- Gauss-Newton damping: 1e-4.

These are benchmark parameters and are written to `metadata.json`.

## Outputs

The files are unchanged so Step 9.0 and 9.0.1 can be compared directly:

- `localization_trials.csv`
- `localization_summary.csv`
- `query_scans.csv`
- `metadata.json`

Additional Step 9.0.1 diagnostics include:

- `normal_correspondences` — correspondences surviving normal validity and trimming;
- `mean_abs_plane_residual_m` — final mean absolute point-to-plane residual;
- `matcher=point_to_plane`.

## Gate before Step 9.1

Use the stricter gate motivated by the Step 9.0 failure:

- `0.5 m / 1 degree`: >= 90% success;
- `1 m / 3 degree`: >= 80% success;
- both should have median final error <= 0.5 m / 1 degree.

The `2 m / 5 degree` result should show meaningful recovery but is not required to be perfect. `5 m / 10 degree` remains a stress test.

Do not introduce native BST geometry until the conventional voxel point-to-plane baseline clears this gate.

## Scientific scope

Step 9.0.1 is still **not** a BST localization result. It validates a conventional voxel scan-to-map objective that later steps can reuse for native block geometry. No representation claim should be made from this step.
